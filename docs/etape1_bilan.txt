2.3. Pourquoi Docker au lieu d'une installation directe ?

  - Reproductibilite : le meme docker-compose.yml redonne
    exactement les memes versions partout (notrement si on
    réinstallé sur une autre machine, ou chez le jury).
  - Propriete : rien ne salit le systeme Windows ; si on veut
    tout supprimer, on supprime les conteneurs et c'est fini.

2.5. Le graphe de la ville (les chiffres)

  Total noeuds : 12
    - 2 zones (Z1 Tunis Centre, Z2 Tunis Nord)
    - 2 postes electriques (P1, P2)
    - 2 antennes telecom (T1, T2)
    - 2 hopitaux (H1, H2) : H1 n'a PAS de groupe electrogene

    - 3 routes (R1, R2, R3), toutes en statut CLEAR

2.6. Trois mots-cles Cypher indispensables

  - MERGE  : "cree le noeud/lien s'il n'existe pas, sinon utilise
    celui qui existe" -> idempotent (ne fait jamais de doublons).
  - MATCH  : "retrouve ce qui existe deja" (par label + id).
  - CREATE CONSTRAINT ... IS UNIQUE : regle de base de donnees
    pour interdire des doublons sur l'id.

2.7. Chaine complete de creation du graphe

    (a) On ecrit le plan dans data/seed.cypher
    (b) On le copie dans le conteneur : docker cp seed.cypher ub_neo4j:/tmp/
    (c) On l'execute : docker exec ub_neo4j cypher-shell -u neo4j
        -p urbanbutterfly -f /tmp/seed.cypher
    (d) mots de passe de test : neo4j / urbanbutterfly
    (e) visualization : http://localhost:7474
        Requete bonus pour tout voir :
        MATCH (n) OPTIONAL MATCH (n)-[r]->(m) RETURN n, r, m

2.8. Le test de validation de la section 24

On simule la panne du poste P1 en mettant son statut a OFFLINE.
Neo4j retrouve automatiquement les infrastructures touchees :
T1 (antenne) et H1 (hopital), critiques parce que H1 n'a pas de
groupe electrogene de secours.

Requete Cypher du test :
  MATCH p = (x)-[:DEPENDS_ON*1..5]->(p0:PowerStation {id:'P1'})
  WHERE p0.status = 'OFFLINE'
  RETURN x.id, x.kind, length(p) AS profondeur

Pourquoi ca marche : la relation DEPENDS_ON encodes deja la
dependance; Neo4j parcourt le "chemin" depuis la panne vers ceux
qui en dependent. La profondeur = nombre de sauts.

2.9. Pourquoi le seed est "idempotent"

MERGE + IF NOT EXISTS permettent de rejouer seed.cypher infinite
fois sans jamais dupliquer de donnees. En pratique : le jour de la
soutenance on peut repartir d'une base vide et reconstruire la
ville a l'identique en 2 commandes = preuve de reproductibilite
des resultats.

2.10. Un detail d'architecture appris : le pattern polyglot

Les identifiants des infrastructures au Neo4j correspondront
future Ã  des documents dans MongoDB : le graphe porte les RELATIONS,
le document store porte le DETAIL des donnees. C'est la raison
pour laquelle les 2 bases sont toutes les deux presentes (
approach "polyglot persistence" du cahier des charges).
